# 캐릭터 절차적 애니메이션 시스템 개선

## 작업 요약

프로젝트 전수 분석으로 Three.js·GLTF 모델이 아닌 Angular/Pug DOM 파츠와 CSS 3D 렌더링 구조임을 확인했습니다.
기존 캐릭터 디자인과 지도·인증·채팅 흐름을 유지하면서 이동/회전, 상태 머신, 감정 액션, 원격 좌표 보간 책임을 분리하고 절차적 애니메이션을 적용했습니다.

## 원문 요청사항

```text
현재 웹앱의 지도 화면에 3D 아바타가 표시되어 있지만, 이동 시 캐릭터 모델 전체가 좌표만 따라 움직이고 있어서 생동감이 부족하다.

프로젝트 전체 코드를 먼저 분석한 뒤, 현재 사용 중인 3D 엔진과 아바타 구조를 유지하면서 캐릭터 애니메이션 시스템을 개선해줘.

목표:
- 캐릭터가 가만히 있을 때도 살아 있는 것처럼 보이게 한다.
- 이동, 방향 전환, 점프, 감정 표현이 자연스럽게 연결되게 한다.
- 기존 지도 이동, GPS, 멀티플레이, 채팅 기능은 깨지지 않게 한다.
- 모바일과 웹 브라우저에서 성능 저하가 크지 않게 구현한다.

필수 작업:

1. 현재 구조 분석
- Three.js, React Three Fiber, Babylon.js, Unity WebGL, GLTF 등 어떤 방식으로 캐릭터를 렌더링하는지 확인한다.
- 캐릭터 컴포넌트, 이동 상태, 좌표 갱신, 방향 계산, 애니메이션 클립 로딩 위치를 찾는다.
- GLB/GLTF 모델에 포함된 애니메이션 클립 목록을 확인한다.
- 애니메이션이 없는 모델이라면 코드 기반 보간 애니메이션을 적용할 수 있도록 구성한다.

2. 캐릭터 상태 머신 구현
캐릭터 상태를 최소 다음과 같이 분리한다.

- idle
- walk
- run
- jump
- wave
- emote
- sit

상태 전환 우선순위는 다음 기준을 사용한다.

jump > wave/emote/sit > run > walk > idle

캐릭터 이동 속도와 사용자 입력을 기반으로 자동으로 상태를 변경한다.

예시:
- 이동하지 않음: idle
- 낮은 속도로 이동: walk
- 일정 속도 이상: run
- 점프 입력: jump
- 감정 버튼 클릭: emote
- 손 흔들기 버튼 클릭: wave

3. Idle 애니메이션
캐릭터가 정지 상태일 때 다음 효과를 적용한다.

- 상체 또는 캐릭터 전체가 아주 미세하게 위아래로 움직이는 호흡 효과
- 몸이 좌우로 아주 조금 흔들리는 효과
- 머리가 미세하게 움직이는 효과
- 가능한 모델이면 3~5초 간격의 눈 깜빡임
- 지나치게 흔들리거나 화면이 산만해지지 않게 작은 값으로 설정

애니메이션 클립이 있으면 AnimationMixer를 사용하고, 없으면 sin 함수와 lerp를 이용한 절차적 애니메이션으로 구현한다.

4. 걷기 및 달리기
이동 속도에 따라 walk와 run을 구분한다.

걷기:
- 팔과 다리가 서로 반대 방향으로 자연스럽게 움직임
- 몸이 미세하게 위아래로 움직임
- 이동 속도에 맞춰 애니메이션 재생 속도 조절

달리기:
- 걷기보다 팔과 다리 움직임 범위를 크게 적용
- 몸을 이동 방향으로 약간 기울임
- 빠른 이동 속도에 맞게 애니메이션 재생 속도 조절

실제 GLB 애니메이션 클립이 있다면 해당 클립을 우선 사용하고, 없으면 본 또는 캐릭터 파츠를 직접 회전시키는 방식으로 구현한다.

5. 부드러운 방향 전환
캐릭터가 이동 방향으로 즉시 회전하지 않게 수정한다.

- atan2를 사용해 목표 회전각 계산
- lerpAngle 또는 quaternion slerp를 사용해 부드럽게 회전
- 프레임 독립적으로 동작하도록 deltaTime 적용
- 180도 회전에서도 갑자기 반대 방향으로 도는 현상이 없도록 최단 회전 경로 사용
- 기본 회전 반응 시간은 약 0.1~0.25초 수준으로 설정

6. 이동 보간
멀티플레이 또는 GPS 좌표가 일정 주기로 들어오는 경우 캐릭터가 순간이동하지 않게 한다.

- 현재 위치와 목표 위치를 분리
- 매 프레임 lerp 또는 damp 방식으로 목표 위치까지 이동
- 큰 좌표 차이가 발생한 경우에만 순간이동 처리
- 원격 사용자 캐릭터도 동일하게 부드럽게 움직이게 구현
- 네트워크 패킷 간격 때문에 캐릭터가 떨리지 않도록 스냅샷 보간 또는 짧은 버퍼 적용 검토

7. 점프
간단한 점프 기능을 추가한다.

- 점프 시작
- 상승
- 최고점
- 하강
- 착지

착지 시 캐릭터가 아주 살짝 눌렸다가 원래 크기로 돌아오는 squash 효과를 추가한다.
점프 중에는 walk/run 애니메이션보다 jump 상태를 우선한다.
연속 점프가 과도하게 발생하지 않도록 쿨다운을 둔다.

8. 감정 표현 및 손 흔들기
캐릭터 상호작용용 액션을 추가한다.

필수 액션:
- 손 흔들기
- 기쁨
- 놀람
- 하트

UI에는 캐릭터 근처 또는 기존 컨트롤 영역에 작은 감정 버튼을 추가한다.

감정 실행 시:
- 일정 시간 동안 해당 애니메이션 재생
- 캐릭터 머리 위에 이모지 또는 작은 파티클 표시
- 약 1.5~2.5초 후 이전 이동 상태로 복귀
- 같은 액션이 연속으로 중첩되지 않게 처리
- 멀티플레이 구조가 있다면 다른 사용자에게도 감정 상태가 전달될 수 있도록 이벤트 구조를 분리

9. 다른 캐릭터 바라보기
가까운 사용자 또는 현재 채팅 중인 상대가 있으면 머리나 상체가 상대를 약간 바라보도록 구현한다.

- 일정 거리 안에 있을 때만 적용
- 머리 회전 최대 각도 제한
- 몸 전체가 과도하게 비틀리지 않도록 제한
- 대상이 사라지면 자연스럽게 정면 복귀
- 구현이 모델 구조상 어렵다면 머리 본 제어 대신 캐릭터 전체의 미세한 시선 회전으로 대체

10. 그림자 및 접지감
현재 캐릭터 아래 그림자가 단순하게 보이므로 다음을 개선한다.

- 캐릭터 높이에 따라 그림자 크기 또는 투명도 변경
- 점프 시 그림자가 조금 작아지고 연해지게 처리
- 지면 위에 캐릭터가 떠 보이지 않도록 모델의 발 위치와 기준점을 확인
- 기존 렌더링 성능을 크게 해치지 않는 범위에서 적용

11. 코드 구조
다음처럼 책임을 분리해 유지보수하기 쉽게 구성한다.

예시:

- useCharacterMovement.ts
- useCharacterAnimation.ts
- characterAnimationState.ts
- EmoteControls.tsx
- RemoteAvatarInterpolator.ts

실제 프로젝트 구조에 맞게 파일명은 조정해도 된다.

애니메이션 로직을 한 컴포넌트에 전부 넣지 말고 다음을 분리한다.

12. 성능
```

## 남은 참고사항

- 프로젝트에는 GLB/GLTF, 본, AnimationMixer 및 실제 3D 엔진이 없으므로 DOM 파츠 기반 절차적 애니메이션으로 구현했습니다.
- 실제 GPS 좌표 이동과 원격 멀티플레이 아바타 스트림은 현재 프로젝트에 없으며, 보간기와 감정 이벤트 계약까지만 준비했습니다.
- 브라우저 콘솔과 실제 모바일 기기에서의 장시간 성능·레이아웃 육안 검수는 별도 환경에서 필요합니다.
