## 사용자 원 요청

> 새로고침 후에도 정한 캐릭터가 유지되어야 하는데 계속 기본 캐릭터로 변하는 문제를 확실히 수정해 달라는 요청.

## 재확인한 원인

브라우저 저장 문제 외에 새로고침 전용 실행 순서 문제가 있었습니다. Angular는 비동기 `ngOnInit` 완료를 기다리지 않고 `ngAfterViewInit`을 호출하므로, URL과 로그인 세션에서 생활권 방을 복원하기 전에 캐릭터 런타임 시작 시점이 지나갔습니다. 이후 방 화면은 나타나지만 선택한 GLB 렌더러가 시작되지 않아 기본 대체 캐릭터가 화면에 남았습니다.

브라우저 저장소만으로는 제한된 iframe·브라우저 환경에서 안정성을 보장하기 어려운 문제도 있었습니다.

## 변경 내용

- 세션·URL 복원과 화면 렌더가 완료된 뒤 생활권 방의 3D 캐릭터 런타임을 다시 시작합니다.
- 브라우저 뒤로가기/앞으로가기로 방을 복원할 때도 렌더 완료 후 같은 초기화를 실행합니다.
- 사용자 테이블에 캐릭터 JSON 저장 필드를 추가하고 현재 데이터베이스에 마이그레이션을 적용했습니다.
- 캐릭터 모델·외형을 변경하면 로컬 저장과 함께 로그인 계정 서버에도 순차 저장합니다.
- 새로고침과 로그인 시 서버 저장값을 가장 먼저 복원하고 로컬 저장값은 마이그레이션·오프라인 보조 수단으로 사용합니다.
- 빠른 연속 변경은 180ms로 합쳐 저장하고, 완료 단계에서는 즉시 서버 저장을 요청합니다.
- 계정 전환 시 이전 계정의 저장 상태가 섞이지 않도록 사용자별 저장값과 서버값을 다시 불러옵니다.
